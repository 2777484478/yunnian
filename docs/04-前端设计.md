# YunNian 云辇 · 前端页面结构与路由设计

> 技术栈：React 18 + TypeScript + Vite + Ant Design 5 + React Router 6
> 视觉基调：**参考阿里云控制台** —— 浅灰底、纯白卡片、蓝色主色、紧凑信息密度

### 布局要点（对齐阿里云）

- Header 纯白 + 1px 下边框，无阴影；左侧 logo 区宽 224px，右侧与 Sider 分栏线对齐
- Sider 纯白 + 右侧 1px 分割线；菜单项 38px 高、圆角 6、选中态 `#eaf2ff` 底 + `#1677ff` 字
- 内容区底色 `#f4f6f9`，卡片纯白 + 1px `#eceef2` 边框 + 极轻阴影（`0 1px 2px rgba(20,26,38,.03)`）
- 表格头 `#fafbfc`，行 hover `#f7faff`，字号 13px（信息密度高）
- 危险操作（下线、删除、回滚）统一用 `danger` 红色，且必须二次确认

### 品牌标识与 Logo

| 项 | 值 |
| --- | --- |
| 中文名 | **云辇**（YunNian 的汉语本字，「辇」取承载、运载之意 —— 对应平台"把构建产物运到各环境"的职责） |
| 英文/拼写 | `YunNian`（保留，作为代码、包名、域名与接口前缀的统一拼写） |
| 完整称谓 | `YunNian 云辇 · AI 运维管理发布平台`（页面标题、登录页、顶栏统一用这一句） |
| Logo 图形 | 橙色渐变（`#ff8a2b → #ff6a00`）圆角方块 + 白色云；圆角 7px（28px 尺寸）/ 8px（32px 尺寸） |
| Logo 实现 | `src/components/Logo.tsx` 的 `<LogoCloud />`（纯矢量路径，**不依赖中文字体**，任何环境都不会出现方块字） |
| 浏览器图标 | `public/favicon.svg`，并把同一份 SVG **内联为 data URI 写进 `index.html`** —— 单文件产物用 `file://` 打开时无外部依赖，标签页图标照样显示 |
| 修改约定 | 改 logo 需要**同时**更新 `Logo.tsx` 与 `favicon.svg`（`index.html` 里的 data URI 由 `favicon.svg` 转义生成），两处必须一致 |

> 早前版本用中文字符「云」直接渲染 logo 方块，改为矢量云形有两个原因：
> 一是 CJK 字符在缺失中文字体的环境下会渲染成方块，二是在 16px 的标签页尺寸下笔画会糊成一团。

## 4. 各页面结构细化

### 4.1 概览 `/overview`

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 动态横幅 | 问候语（按时段）+ 实时时钟（秒级）+ 状态 chips（集群连通 / 进行中构建 / 待审批 / 告警服务） | `stats` + 前端时钟 |
| 指标卡 ×4 | 纳管项目（前/后端拆分）、今日构建（环比）、构建成功率、环境/服务（正常·告警·异常） | `GET /system/stats` |
| 构建趋势（14 天） | 面积图：构建总量 + 失败数（虚线） | `stats.trend` |
| 构建结果分布 | 环形图（成功/失败/进行中/取消/**已中断**）+ 平均耗时进度条 | `stats.builds` |
| 最近构建 | 8 行表格：项目、构建号、分支、状态、耗时、触发人、时间 | `GET /builds?pageSize=8` |
| 环境资源状态 | 环境列表 + 资源状态徽标（**只反映节点 CPU/内存水位，不是服务健康**）+ 服务数，点击进入环境详情 | 环境走 `GET /environments`，**资源徽标与「N 个待关注」走 `/environments/{key}/resources` + `/services` 的实时值**（见 §4.6 口径说明） |
| 待处理事项 | 待审批部署、24h 失败构建、异常服务、Harbor 容量、**平台重启中断的构建（条件出现）** | `stats.todos`；⚠️ **「异常服务」不用 `stats.abnormalServices`** —— 那是 `service_instance.status` 的库内计数（纳管时写入的期望值），实测会把集群里 running 的服务报成异常。该字段已于 2026-10-09 从后端删除 |

> ⚠️ 上表其余行的"数据来源"仍是**原型期写法**，与实现已经不一致：`stats`（`GET /system/stats`）
> 只提供绝对值，趋势/分布类图表都是前端从列表接口聚合的（后端没有为每张图开接口）。
> 以 `pages/Overview.tsx` 的实际取数为准。
>
> 另：`GET /system/stats` 的 `abnormalServices` 与 `/environments` 下发的
> `status / cpuUsage / memUsage` 都是**平台库口径**，前端已不再用它们表示"现状"。
> `abnormalServices` 已于 2026-10-09 **从后端删除**（不再下发）；顶栏「N 个环境资源紧张」
> 也已改为读 `/environments/{key}/resources` 的实时值。`/environments` 的
> `status / cpuUsage / memUsage` 仍保留，但前端不用于表示"现状"。
>
> **「已中断」为什么在环形图上占独立一瓣**：它与「已取消」在饼图上容易撞成同一个灰扇区，
> 但两者是相反的事 —— 一个是**有人主动叫停**，一个是**平台重启打断**。
> 合并等于把运维动作说成用户决策。
> 同理，**平均构建耗时 / 最快最慢区间都排除 `interrupted`**：它不是一次完整的构建，
> 耗时只到被切断那一刻，拉进来会让「流水线有多快」这个指标随平台重启频率上下浮动
> —— 一个衡量流水线速度的指标，不该被运维动作污染。

**动态效果约定**（样式集中在 `src/styles/motion.css`，原型已实现）：

- 指标卡数字**从 0 滚动到目标值**（easeOutCubic，900ms；`AnimatedNumber` 组件，等宽数字 `tabular-nums` 防抖动）
- 表格里「进行中」构建的耗时位置换成**流动条纹进度条**（`.yn-progress-live`）；静态耗时仍是文字
- 顶部横幅：网格缓慢平移 + 右上角光斑游移；集群/环境状态用**脉冲点**（`.yn-live-dot`）
- 卡片 hover 抬升 3px + 阴影加深；首屏卡片组用 `.yn-stagger` 逐项延迟入场
- 全部动效遵守 `prefers-reduced-motion: reduce`，用户开启后自动关闭

> 动效只用来表达"信息在流动"（正在构建 / 正在部署 / 实时刷新），不做无意义装饰。
> 指标升降配色按**对指标是好是坏**决定（成功率 +1.8% 显示绿色，失败率 +2% 显示红色），不按数字方向取色——
> 配色类名为 `.yn-delta-good` / `.yn-delta-bad`，旧的 `.yn-delta-up/.yn-delta-down` 已废弃。
| 构建耗时排行 | 水平条形图（平均耗时 TOP 7） | `GET /projects?sortBy=avg_duration` |

### 4.2 项目管理 `/ci/projects`

- **筛选区**：关键字（名称/标识/负责人）、类型 Segmented（全部20/前端10/后端10）、构建方式、启用状态
- **批量栏**（选中行时出现）：批量编译 / 批量停用 / 取消选择
- **表格列**：项目名称（标识·团队）、类型、构建方式、最近构建状态、**最近镜像版本（地址+Digest）**、最近构建时间（+耗时）、成功率、状态、操作
- **行操作**：`编译` / `构建历史` / `编辑` / `删除`
- **一键编译弹窗**：
  1. 顶部信息条（项目标识 / 构建方式 / 目标镜像）
  2. 构建分支（可搜索可选可输入）、镜像 Tag（留空按规则生成）
  3. **构建参数覆盖**（KV 编辑器，密文开关）
  4. 构建完成通知开关
  5. 底部展示该项目最近 3 次构建历史
  6. 提交 → `POST /builds` → 成功后 toast 并跳转构建记录页
- **新建/编辑抽屉**（880px，**一页到底、5 个分区**）：
  - 版式：标签在左、控件在右，每个格子下面跟一句说明（一页到底）。
    改之前是 3 个 Tab（基本信息 / 仓库与构建 / 构建参数），两个具体毛病：
    ① 选了「自定义脚本」还照样渲染 Dockerfile 路径与构建上下文，用户不知道该不该填；
    ② 配仓库时看不到镜像配置，切过去又忘了刚才填了什么。
  - **只有一个新建入口**（`项目管理 › 新建项目`）。构建方式是**表单里的一个字段**
    （`Jenkins Job` / `自带 Dockerfile` / `自定义脚本`，**默认 Jenkins Job**），
    选了之后下面渲染哪一组字段跟着变。以前是门外两个菜单项（新建项目 / 新建 Jenkins Job 项目），
    而进去之后 `buildMethod` 是**禁用**的 —— 选错只能退出来重进，编辑时更是完全不能换方式。
  - `基本信息`：名称、标识（编辑态禁用）、类型、团队、负责人、启用状态、描述
  - `代码仓库与凭据`：仓库地址、默认分支、**账号**、**密码 / 令牌**、**「测试连接」按钮**
    - 密码**编辑态永远为空**，提示「已保存，留空表示不修改」—— 任何"把密码回填进输入框"的做法
      都等于把明文发到浏览器，会被密码管理器、前端日志、截图各留一份。
    - 「测试连接」就叫 `POST /projects/test-connection`，不传密码时后端回落已保存的凭据：
      「改完地址点一下测试」不该逼用户重敲一遍密码。
    - 结果行成功时只显示 `连接成功（读到 N 个分支，用时 Xms）`，**不重复拼后端的 message**
      （后端成功时的 message 就是「连接成功」，拼出来是「连接成功：连接成功」）。失败时给
      `连接失败：<人话>`，原始输出折叠在下面的 Alert 里。
    - 那个 `N` 取的是 `branchTotal`（远端真实分支数），**不是** `branches.length`。
      `branches` 会被后端截到 100 条，拿它的长度当"读到多少分支"是句假话：
      仓库有 229 个分支时会显示「读到 100 个分支」。截断时明说「已列出前 100 个」——
      实测渲染是 `连接成功（读到 229 个分支，已列出前 100 个，用时 410ms）`。
    - 选分支的控件（构建弹窗里）是 **`AutoComplete` 而非 `Select`**：分支名可以是任意字符串，
      而 `Select`（不带 tags 模式）只能从选项里挑，"支持直接输入"就成了句空话。
      因此第 100 名之外的分支**仍可直接输入**，列表截断只是少了个便利。
  - `镜像与版本`：镜像仓库地址、镜像名称、**Tag 规则**（变量说明 + 「预计下次构建产出」实时预览）
    - 变量说明表必须**列全**：除 5 个占位符外，还要有 **`{buildNo+N}` 这个偏移写法**。
      漏了它，用户只能靠猜 `2.2.0.{buildNo+995}` 是否合法 —— 实测就是被这么问的
      （「你这里不显示，我怎么知道有什么规则？」）。
    - 认不出的花括号写法**在表单里就拦下**（`unknownTagTokens`，提示写出可用写法）：
      后端 `renderTag` 只替换已知占位符，剩下的会**原样**拼进 tag，而 docker 不允许 tag 里
      有花括号 —— 失败点会跑到 `docker build -t` 报 `invalid reference format`，
      与"Tag 规则写错了"毫无关系。
  - `构建流程`：构建方式 Segmented（自带 Dockerfile / 自定义脚本）
    - 选 `自带 Dockerfile` → Dockerfile 路径 + 构建上下文路径
    - 选 `自定义脚本` → **脚本编辑器**（16 行高、等宽字体、变量说明表 + 「恢复默认脚本」）
      - 默认脚本由 `GET /projects/default-build-script?type=` 下发，**前端不硬编码**：
        默认脚本必须和构建机上的镜像地址、注入的变量名保持一致，各留一份副本迟早会漂移。
      - 只在脚本为空时自动填。编辑一个已有脚本的项目时进去就覆盖成默认值，
        等于**偷偷丢掉用户写的东西**，而保存按钮还在那儿，看起来像是他自己改的。
      - 「恢复默认脚本」是显式动作，点了才覆盖。
    - 切换构建方式时，另一边的值**保留不清空**（切回来还在）。
  - `构建参数`：KV 编辑器；**不预置任何值** —— 预置一个没人读的值，用户会以为它已经生效了。
  - `{buildNo}` 预览用 `totalBuilds + 1` 估算并标成「**预计**下次构建产出」：
    它终究是算出来的，真正落库的以构建记录为准。
    - 渲染走 `previewTag()` —— 它是**前端复刻**后端 `renderTag` 的口径（含 `{buildNo±N}` 偏移、
      负值夹 0），两边共用同一个正则 `reBuildNo`。
      曾经这里只会 `.replace('{buildNo}', …)`，而它**匹配不到** `{buildNo+995}`（花括号位置不同），
      于是预览把 `2.2.0.{buildNo+995}` **原样**显示出来，看着就像平台会产出一个带花括号的 tag。
      **改后端 `renderTag` 时务必回来改这里**（预览是用户理解版本号的第一入口）。
  - 布局常量 `FORM_LABEL_WIDTH = 104` 单独抽出：有一处不属于任何字段的控件（「测试连接」按钮）
    要跟输入框左边缘逐像素对齐，而它又不能包在 `Form.Item label=" "` 里 ——
    那个写法在 `requiredMark="optional"` 下会渲染出一个**空标签 + 「（可选）」**的怪东西，
    正好出现在用户最需要看明白的地方。
- **删除**：`modal.confirm` 说明「构建记录与镜像版本不再展示，已部署服务不受影响，建议改停用」

### 4.4 构建记录 `/ci/builds`

- 顶部 4 个指标卡（今日构建/成功/失败/进行中）
- **正在构建**区块：实时进度条 + 阶段文案 + 「实时日志」直达
- 筛选：关键字（项目/镜像/构建号/Commit）、项目下拉、类型 Segmented、时间范围、状态（含**「已中断」**）
- 表格列含进度条（running）与阶段（queued）
- **自动刷新**（2026-10-13 补）：页头「自动刷新」控件，默认 **3 秒**，可调 5/10/30 秒或关闭
  （偏好按 `ci-builds` 作用域存，与项目列表互不影响）。轮询 `/builds`（列表 + 正在构建面板）
  与 `/system/stats`，**刻意不轮询 `/projects`**（筛选下拉的候选属纳管清单，不会自己变）。
  走静默刷新（不闪加载遮罩、单拍失败不把整页打成错误态），切后台暂停、切回立刻补刷。
  构建状态本来就是**平台后台**在改的，没有它页面只会永远停在「构建中」、逼用户按 F5。详见 §6.3。
- 行操作：`日志`（抽屉，running 时逐行流式追加 + LIVE 呼吸灯）、`AI 诊断`（**仅失败构建出现**）、`取消`（仅运行中/排队中）
- **`interrupted`（平台重启中断）的呈现**（2026-10-09 补）
  - 状态标签橙色「已中断」（`PauseCircleFilled`），与「失败」红、「已取消」灰区分开
  - **耗时列显示「—」而不是「0s」**：它原本是 `queued`（live → 「—」），被标成 `interrupted` 后
    若照常渲染 `duration`（0）就变成「0s」，把「没跑过」说成「跑了 0 秒」。
    口径与 `DeployList` / `RollbackList` 的耗时列统一：`isLive(status) || !duration → '—'`
  - `AI 诊断` 入口不出现（没有失败可归因）；若给出提示，文案必须是「因平台重启中断，
    没有失败原因可归因」，**不能**掉进兜底话术「构建结束后，失败时可用 AI 归因」
    ——对一条已结束的记录说「构建结束后」，等于告诉用户它还在跑
  - 日志抽屉**不渲染 Steps**，改渲染一句实话的 warning Alert：那个控件回答的是「走到哪一步了」，
    而它的取值是从 status 猜出来的硬编码下标，硬套会让一条中断在拉代码阶段的构建显示成「编译构建已完成」
- `AI 诊断` 抽屉内的结论**必须标注来源**：`由模型通道「x」阅读构建日志生成` 或 `平台错误码规则匹配`；
  模型不可用时后端降级为规则结论并用 notice 说明原因，前端照实展示，不冒充模型输出
- 日志抽屉内：Steps 阶段条、**AI 失败归因卡**、终端风日志面板（深色，行号 + 着色 + 关键字过滤 + 跟随滚动 + 复制/下载）
- **失败真因（`errorMessage`）的呈现**（2026-10-10 补，`components/FailureReason.tsx` 与部署页共用）
  - 状态列在「失败 / 已中断」标签下**直接给出一行真因**（超长省略号 + 悬浮看全文），
    颜色随标签（失败=红 `#ff4d4f`，中断=橙 `#fa8c16`）。
    藏进抽屉等于逼用户多点一次才能知道这一行为什么红。
  - 日志抽屉顶部与 `AI 诊断` 抽屉的概要里都给完整原文 —— 用户点「日志」问的就是「为什么失败」，
    让他自己在几百行里找那条 `error`，等于把我们刚记下来的东西又藏回去。
  - **兜底顺序是「真因 → 错误码 → 一句实话」**：落这列之前的旧记录两者皆空时显示
    「未记录失败原因」，**不留白** —— 留白会被读成"这条没有失败原因"，而事实是"当时没记下来"。
  - **`errorMessage` 是事实，`aiDiagnosis` 是结论**：后者按需触发、可能走模型、也可能降级成
    错误码套话。两者必须分开排布（事实在前），排查顺序是"先看事实，再信结论"。

### 4.5.1 批量任务（批量打包 / 批量发布）

面向"一次发版 N 个微服务"的高频场景，把逐个项目点一遍的操作收敛成一个批次。
两个入口共用同一套执行面板组件（`src/components/BatchRunner.tsx`）。

**入口**

| 位置 | 按钮 | 说明 |
| --- | --- | --- |
| 项目管理 `/ci/projects` | 头部「批量打包」/ 勾选行后的「批量编译」 | 勾选行会带入向导预选 |
| 发布拓扑 `/cd/topology` | 控制条「批量发布」（分段控件右侧） | 默认目标环境取当前链路首个环境 |

**CI 批量打包向导**（`BatchBuildWizard.tsx`，3 步）

1. **选择项目** —— 卡片网格 + 搜索/类型筛选；「全选当前 / 反选 / 清空」；卡片显示类型、构建方式、最近构建状态、负责人
2. **构建配置** —— 构建分支、并发 Runner 数（默认 3）、Tag 生成方式（按各项目规则 / 统一 Tag）、
   构建参数（底部折叠区，统一追加或覆盖）；右侧「构建清单」表格供提交前逐条核对 Tag 与镜像地址
3. **排队打包** —— 执行面板（见下）

**CD 批量发布向导**（`BatchDeployWizard.tsx`，3 步）

1. **选择服务** —— 顶部选目标环境（按发布阶段排序的卡片）；下方服务表格列出
   「当前环境版本 / Harbor 最新版本 / 变更标记（首次部署·有更新·已最新）」；
   筛选分段为 `全部 / 有更新 / 未部署 / 已最新`，并提供「仅选有更新」一键勾选
2. **确认版本** —— 进入即自动执行 **Harbor 版本读取**（连接 → 鉴权 → 批量查询 artifacts → 按 push_time 取最新，
   逐条回显），读取完成后列出每条服务的「当前版本 → 可修改的目标版本 + 副本数」，逐条核对后再提交；
   需审批的环境给出审批人提示
3. **排队发布** —— 执行面板，串行发布（同一环境不并发更新，避免滚动发布互相抢占资源）

**执行面板（BatchRunner）**

- **队列**：左侧任务卡（状态图标 / 进度条 / 耗时 / 目标 tag），支持单任务取消、全部取消、暂停播放、
  1x / 2x / 4x / 8x 播放速度
- **实时日志**：右侧日志面板接"实时流"，行首时间戳 = **真实播放时刻**（不是预置的历史时间），
  底部显示「已输出 N 行 · 持续接收中」；
  可切「当前任务 / 合并视图」——合并视图把所有任务日志按时间交织，行首带任务短名，接近 Jenkins 聚合控制台
- **跟随**：默认跟随执行中的任务；批次结束后自动定位到**第一个失败任务**，直接看失败原因
- **统计**：批次总进度、执行中/成功/失败/排队/取消/**已中断**计数、已用时、预计剩余、脚本权重
- **收尾**：有失败**或已中断**时给出重试入口（「重试未成功项」）与 AI 归因提示

> ⚠️ **`interrupted` 必须单列，不能并进成功也不能并进失败**（2026-10-09）。
> 漏掉它，`!failed && !canceled` 会把一批「跑了一半就没了」的任务判成「全部成功」，
> 弹出一句绿色的「批量发布完成」—— 那是这批任务里最贵的一个谎，
> 因为用户看到绿色就关页面走了。所以 `BatchResult` 有独立的 `interrupted` 计数，
> 且两个向导的 `handleFinish` 判定都是 `allOk = ... && !r.interrupted`。

**日志与真实后端的对应关系**

原型里日志由前端按"帧"播放（`src/mock/batch.ts` 预生成 `{ text, pause }` 序列，
`scriptsSeconds` 给出理论耗时）。接真后端时：

- 每一行日志改为 **SSE 事件**（`event: log`，`data: { taskId, line }`），时间戳由服务端给；
- `pause` 不再需要，播放速度 / 暂停只是前端观看体验，不影响服务端执行；
- 任务状态改为 `event: task-status`，队列顺序与并发数由服务端的调度器决定。

**产物回写**

- CI 批次：每个任务结束时回写一条 `BuildRecord` 到构建记录（`BUILDS.unshift`），
  因此在 SPA 内切到「构建记录」能看到本批次的记录（含分支、镜像地址、日志、AI 归因）
- CD 批次：服务发布成功时回调拓扑页，命中的节点走一遍「部署中 → 运行正常」推进（当前项目维度）

### 4.6 环境管理 `/cd/environments`

- 视图切换：**卡片** / 表格（Segmented）
- 卡片内容：环境名 + 需审批标签 + 状态徽标；`key · namespace`；集群名 + 版本；构建方式/节点数/服务数/待关注数标签；CPU·内存·项目 三个指标块；两条用量进度条；底栏（入口域名 / 负责人）
- 表格视图列：环境名称、资源状态、集群/Namespace、部署方式、服务/项目数、资源用量（双进度条）、审批、负责人、状态、操作
- 顶部指标卡：环境总数、资源正常环境、纳管服务、待关注服务

**资源数值与「待关注」的口径（2026-10-09 定）**：本页（含概览页、环境详情页头）的
`资源状态` 徽标、`CPU/内存`、`资源用量` 一律来自 `GET /environments/{key}/resources`
（实时），**不读 `environment.cpu_usage / mem_usage / health_status` 快照** ——
后者只在「同步集群」时写一次，界面拿它当现状就会出现"卡片内存 96%、点进去实时 93%"。
读不到时显示 `—` / 一句原因，不退加快照值。取数与阈值推导统一在 `hooks/useEnvResources.ts`
（阈值与后端 `SyncEnvironment` 逐字一致：≥90 error、≥75 warning）。

服务标签 `N 个待关注` 同理，判据是**集群实时状态**（`utils/live.ts` 的 `isServiceAbnormal`），
不是平台库的 `service_instance.status` —— 后者是纳管时写入的期望值，实测有服务库里记
`pending`（`image` 还是空串）、集群里 running 1/1，会报出并不存在的"1 个待关注"。
读不到集群的服务单列一档，既不算正常也不算待关注。
- 新建环境抽屉：名称、标识、集群、Namespace、部署方式、镜像仓库、入口域名、负责人、**KubeConfig 凭证方式**、需审批 + 审批人、启用状态、描述、环境变量 KV

> 既不能取消（不是 live），也不能审批（不在待审批），只能看着它永远停在「已中断」。

比对时 `toUpperCase()` 后忽略大小写）。它**挡不住脚本化暴力破解**——真正的防爆破必须由后端做
（登录失败计数 + 账号锁定 / 限流 + 服务端下发验证码）。原型阶段只保留交互与视觉，接后端后把校验交回服务端。

**模拟登录逻辑**（全部收敛在 `src/auth.ts`，接后端时只改这一个文件的内部实现）：

- 校验顺序：**先验证码、后账号密码**；验证码不通过时**不进入 loading 态**，直接 `fail()` 返回
- `fail()` 的统一动作：换一张验证码 → 卡片抖动 460ms → `message.error`
- 凭据：**仍由 `DEMO_ACCOUNT` 校验，但页面上完全不展示**（`ops` / `changeme`，
  见 `src/auth.ts`）——评审 / 演示时需手动输入，表单 `initialValues` 为空、无预填
- 校验失败文案：验证码 →"验证码不正确，已刷新，请重新输入"；账号密码 →"账号或密码错误，请核对后重试"
- 成功：写 `localStorage`（token + 用户信息 + 记住我标记）→ 跳回守卫带来的 `from` 地址，无则落 `/overview`
- 路由守卫：`RequireAuth` 包裹 `AppLayout`，未登录时 `<Navigate to="/login" state={{ from }} />`
- 退出登录：顶栏用户菜单 → 清会话 → 回登录页；顶栏展示的姓名 / 角色改为读会话，不再写死在 mock 里
- 生产替换：登录接口返回 JWT（accessToken 存内存 + refreshToken 走 httpOnly Cookie），401 静默刷新

> **接后端时的清理项**：① ~~移除演示账号提示条与「一键填入」~~ **已完成**（2026-09-23）；② ~~表单不再预填凭据~~ **已完成**；

## 6. 状态管理与数据获取

> ⚠️ **本节原稿写的是"打算用什么"（TanStack Query / Zustand / `<Can>`），一期落地时都没引入**
> ——（2026-10-13 已按实际实现改正）。下面这张表是**现在真正在跑的**，不再有"将来的事"。

```
UI 状态（菜单折叠、抽屉开关、表单草稿）      → React useState（没有引入 Zustand）
服务端状态（列表、详情、统计）                → 自研 useApi（src/hooks/useApi.ts）
变更操作（提交构建、部署、回滚）              → 调 useApi 的 refresh() / refreshSilent() 重拉
列表按秒自动刷新                              → useAutoRefresh + AutoRefreshButton + useApi.refreshSilent
实时日志 / 流式回答                          → useLogStream / useJobLogs（统一走 api/sse.ts）
当前用户与权限点                              → getSession() / hasPerm()（src/auth.ts）
```

### 6.1 SSE Hook 约定

```ts
// 页面只调 hook，事件契约与解析都集中在 api/sse.ts 的 subscribeLogStream
const { lines, ended } = useJobLogs({
  id, live, stream: buildApi.stream, fetchHistory: buildApi.logs,
});
```

- **底层不是原生 `EventSource`**：`EventSource` 不能带 `Authorization` 头，而本平台的流接口要鉴权，
  所以用 `subscribeLogStream`（`api/sse.ts`）基于 fetch 流实现，**一份契约只有一个实现**
  （批量执行引擎 `BatchRunner` 也复用它，后端加事件时不会漏改某一处）。
- 历史日志与流式日志**字段完全一致**（`seq/ts/level/line`），所以不另立类型——否则页面里
  "历史日志"和"实时日志"会变成两种互不兼容的东西。
- 组件卸载 / 流结束要清理；切换对象时先关旧的再开新的。

### 6.2 权限判断

```tsx
{hasPerm('deploy:prod') ? <Button type="primary">部署到正式区</Button> : null}
```

- 没有 `<Can>` 组件（一期未落地），直接用 `hasPerm()` / `hasAnyPerm()`。
- 判断**权限点**而不是角色名；没有权限时**禁用并说明原因**，不要让它点下去吃一个 403。

> ⚠️ 前端隐藏只是体验优化，**后端必须对每个变更接口独立校验权限点**。

### 6.3 自动刷新约定（`hooks/useAutoRefresh.ts` + `components/AutoRefreshButton.tsx`）

**判据一句话：「这个值会不会在用户不操作时自己变？」** 会，就该轮询；不会，就别轮询。

| | 规则 |
| --- | --- |
| 该轮询 | 构建/部署/回滚的状态与进度、集群实时值、环境资源 —— 这些是**别处**在改的 |
| **不该轮询** | 项目/团队/用户等**纳管清单**、配置项、字典。为它们每 3 秒重拉一次纯属白烧 |
| 三件套 | `useApi.refreshSilent`（取数）+ `useAutoRefresh`（调度）+ `AutoRefreshButton`（控件） |
| 必须走静默 | 每几秒闪一次加载遮罩比不刷新更难受；后台那拍失败**不能**把整页打成错误态（一次网络抖动 = 列表没了，而手上那份数据其实还是对的）。失败只记进控件里那句话，下次成功自动清掉 |
| `isBusy` | **必须给**，多接口时取"任一在飞"；否则慢后端下定时器会把请求滚成一片 |
| 后台暂停 | 浏览器**不会**因标签页不可见就停掉 `setInterval` —— 用户开着页面去吃午饭，后端被白打几小时。定时器只在可见时触发，切回**立刻补一次**（并挡掉 1.5s 内的重复派发） |
| **偏好按 scope 分存** | 单一全局键意味着"在某页关了自动刷新 = 所有页面都关了"，后续新接的页面**进去就是关的，看着跟没做一模一样**。CD 视图共用 `'cd'`；构建记录用 `'ci-builds'`（项目列表是历史遗留的全局键，行为保持不变） |
| 不打断用户 | 列表每几秒换一次引用，**弹窗/抽屉的 target 必须存成独立 `useState` 快照**，不能每次渲染从列表 `find()` 派生 |

**当前接入的页面**：环境详情 `'cd'`、发布拓扑 `'cd'`、项目列表（全局键，3s）、
**构建记录 `'ci-builds'`（3s，2026-10-13 接）**。构建记录只轮询
`/builds`（列表 + 正在构建面板）、`/system/stats`，**刻意不轮询 `/projects`**（筛选下拉的候选，属纳管清单）。

> `AutoRefreshButton` 的面板顶部固定显示「当前间隔 + 上次刷新时间 + 后台刷新失败原因」——
> 这几个字是回答"我看到的这份数据有多新"的唯一地方，藏进 Tooltip 反而没人看得到。
