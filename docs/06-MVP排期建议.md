### 1.2 一期实际走的路：三处与最初设计不同

**① 自建构建 Runner 被砍掉，改为复用已有 Jenkins。**

原设计里有一个独立 Runner 进程（Redis 队列领任务 → git clone → `docker build` → push）。
实际走的是把平台项目和 Jenkins Job 绑起来（`project.build_method=jenkins` + `jenkins_job`），
平台负责触发 / 拉日志 / 同步状态。

- **理由**：公司已有 Jenkins。自建 Runner 等于把"构建机怎么维护、怎么扩、怎么清磁盘"
  变成平台自己的问题 —— 对一个人来说这是失控的开销。
- **代价**：Jenkins 构建的产物版本**没有接口可查**，只能逐行解析日志里的 `docker push`
  （`ParsePushedImage`）。解析器**只认确定证据**，读不到就**留空**，不猜版本号。
- **收敛**：`POST /builds` 对 `build_method=jenkins` 直接返回 40901，平台**不代跑** docker 构建 ——
  一个仓库只保留一条构建路径。（曾经不看这个字段，Jenkins 项目被平台跑了一次构建还"成功"了。）

**② 写集群的动作统一收敛到 AppRelease CR。**

- 直改 Deployment 会被 operator **秒拉回**；HPA 托管的负载干脆拒绝扩缩容。
- **平台库的值不是真相**："现在是什么"必须读集群。三种情形不可混：
  `!available`（**没读到**）／`available && !exists`（**确实没有**）／存在。
  **读不到不许回退库值**。
- 前端隔离单位是**服务**（`key={serviceId}` 重挂载），不靠 `destroyOnClose`。

**③ AI 从「复述快照」改成「自己取数」。**

原设计是一次性把事实拼进提示词，模型只能在这张快照里找。实测用户问
「帮我看看测试区192环境 demouser 服务的状态」，助手答"当前上下文没有关于……的数据" ——
功能没坏，但**它答的不是用户问的**。现在挂 8 个只读工具让它自己查。

- **只读是结构性保证**，不是提示词承诺：模型说"我帮你重启了"也没有东西可调。
- **集群密钥不交给模型**：工具在平台进程内执行，模型只看到返回值。
- **来源如实标注**：`source=model` / `source=rule`，前端按它分叉措辞 ——
  把规则结论渲染成"模型分析"，比不给结论更糟。

### 1.3 一期收尾补掉的口（2026-10-10）

原本有三处"看着是通的、其实是空的"，已补：

| 缺口 | 原状 | 现状 |
| --- | --- | --- |
| **失败真因不落库** | 真因只进**易失的日志流**（进程内 + TTL），平台一重启，那条失败单只剩一个机器码。构建侧更糟：`finishBuild` 只打一条 WARN。 | `build_record` / `deploy_record` 各加 `error_message`，**7 个写点**全部写入；DTO 同时下发 `errorCode`（筛选用）+ `errorMessage`（解释用）；截断按**字符**（按字节会在库里留半个汉字） |
| **通知「只配不发」** | 6 条 CRUD，`TestNotifyChannel` **恒回 `ok=false`**"真实投递尚未接入"，全仓搜不到任何发送实现 | 钉钉（**加签**）+ 邮件（SMTP，`smtps`/`starttls` 分开处理）真投递；订阅矩阵生效；三个触发点（构建失败 / 部署失败 / 部署待审批）；结果回写 |
| **本文档过期** | W2 写 NestJS + TypeORM，人力按团队算 | 本次重写 |

两条共通的纪律，写在这里是因为它们是上述缺口的**共同成因**：

- **不做无源的承诺。** 通知的事件枚举里原来有 8 个码，其中 **5 个没有任何代码会触发** ——
  用户勾上、存库、看到勾上了，然后永远收不到。现在枚举收敛到**真的会触发**的三个，
  渠道类型收敛到**真的能发**的两个（邮件 / 钉钉）：**能配置 == 能收到**。
  同一把尺子适用于所有地方：恒为常数的列、必然报错的入口，都不该存在。
- **失败必须显示真因。** 两个具体的坑：`HTTP 200 ≠ 送达`（钉钉无论成败都返回 200，
  真结果在 body 的 `errcode` 里 —— 不解析它就会把"签名错"记成"发送成功"，
  还刷出一个漂亮的 `last_sent_at`）；`failCount=1` 而不是 `3`（凭据错重试无意义，
  `permanentNotifyError` 直接终止重试）。

## 4. 单人项目的自保约定

替代旧稿的「每日站会 / Code Review / 缺陷分级」。**每一条都对应一次真实踩过的坑**，
不是流程装饰：

- **冒烟脚本的两道自保**（`backend/scripts/smoke.sh`）：开头 `rm -f /tmp/smoke-*.json` +
  `/healthz` 预检。原因是「curl 落盘 → 读 JSON 比对」这个模式有**假绿陷阱**：
  curl 一失败就不写文件，比对会读到**上一轮遗留的同名文件**，照样打印 ✓。
  实测踩过 —— 后端其实早就退了，脚本仍报满屏绿。
- **夹具不许写死**。写死一次的代价不只是"几条 401 可见"，而是**整段静默跳过、覆盖度塌一半**，
  脚本照样报绿。现在构建夹具自动发现"第一个非 Jenkins 项目"；纳管项目**全是** Jenkins 时，
  不静默跳过，而是改为断言那条真实契约（`POST /builds` 返回 40901）。
- **改了 Go 必须重编 + 重启再验**：`go build ./...` **不产二进制**，要 `-o bin/yunnian-server`；
  跑旧二进制 = **假绿**。
- **写操作只打靶**：集群写入只用 `default/nginx-demo` 与自建探针（唯一例外是用户点名的
  `default/demobasic`）；冒烟里的部署 / 回滚段**默认关闭**，要跑得显式 `SMOKE_WRITE=1`，
  且动手前会先打印"改谁、改成什么"。
- **前端改完要真机点一次**：接口全绿 ≠ 按钮能用。本项目已靠浏览器实测抓到多个
  "只有真点才会暴露"的静默缺陷 —— 截断的 Markdown 星号原样渲染、点击坐标落在视口外等于点在页面外、
  清掉 localStorage 后读到旧 DOM 导致结论完全反。
- **文档与记忆在同一个改动里回填**：`docs/02·03·04` + `backend/README.md` + 当天工作日志。
  **只写代码不回填，下一个会话就会把一期的口子当成"设计如此"。**

## 5. 明确不做

| 项 | 状态 | 理由 |
| --- | --- | --- |
| **部署失败自动回滚** | ❌ **不做**（2026-10-08 拍板；此前实现过、当天移除） | 回滚**本身也是一次发版**，它同样会失败，届时集群被改到第三个状态，平台只能再报一次错 —— 比不动作更糟。1 副本 `RollingUpdate` 下 `maxUnavailable` 向下取整为 0，**旧 Pod 不会被杀**，服务通常不中断，"谁在跑、跑的是哪一版"是确定的。恢复交给人走**手工回滚链路**（有权限校验、有审批判定、有审计）。代价必须知情：失败的 spec 会留在集群上，所以失败时会往日志流补一行 `warn` 明说这件事 |
| 企微 / 飞书 / 自定义 Webhook 通知 | ⬜ 二期（**已从枚举移除**） | 配得出来却发不出去是"安静的假承诺"。加回来很便宜（都只需一个 URL） |
| Docker Compose / 自定义脚本部署 | ❌ 不做 | 只支持 Dockerfile + K8s/Helm |
| Harbor 界面配置 / 镜像**真删** tag / `/credentials` | ⬜ 按需 | 当前 Harbor 是 public 项目、匿名可读，所以暂时不需要凭据。接 private 仓库或做真清理时，`/credentials` 是前置依赖（`secret_credential` 表 + `crypto.Sealer` 已就绪，缺 service/handler） |
| `runner.mode=agent` | ⛔ **不做**（2026-10-10 拍板：单体单机） | 配成 agent 时构建**明确失败**（`UnavailableBuilder` → `RUNNER_UNAVAILABLE`），**不会**退回平台进程内执行 —— 退回等于给出一条假成功记录。`model/runner.go` 是无引用的预留。⚠️ 此处原先写「任务仍在平台进程内执行」，与实际行为不符，已更正（那正是"重启即中断"的根因） |
| AI 会话持久化 | ❌ 一期不做 | 表里没有会话表，`/ai/conversations` 返回空列表 + `usable:false`，前端据此隐藏入口 |
| 幂等重入队 | ⬜ 未做 | 启动补偿只做了"标记 `interrupted`"这半；反向的"按幂等键重新入队"没做 |
